# 令牌级可用模式：失败内部重放直至成功

## Goal

令牌开启「可用模式」后：New API 接住客户端的一次请求，并在内部模拟客户端持续重新发送同一请求。每次失败都开启一轮全新的执行与选路，中间失败不返回客户端，直到某一轮成功后才把成功响应返回客户端。

## Background / Confirmed Facts

### 产品模型（极简）

```
客户端只发送一次请求
  → New API 内部发起第 1 轮同请求执行
  → 成功：把成功响应回客户端
  → 失败：不回客户端，结束本轮
  → New API 内部发起下一轮全新的同请求执行
  → 每轮重新执行现有选路，允许再次选中前序轮次失败过的渠道
  → 持续循环，直到成功
```

这不是“遍历一次候选渠道”的 failover，而是把客户端跨 HTTP 请求的持续重试迁移为 New API 内部的持续重放。不新造选路算法，不设次数上限。

### 已确认决策

| 项 | 结论 |
|----|------|
| 开关 | **按令牌**，默认关 |
| 选路 | 复用现有：优先级/权重 + model-route primary→overflow |
| 重放语义 | **每轮等价于客户端再次向 New API 发送同一请求**；重新执行现有选路 |
| 渠道复用 | 前一轮失败过的渠道可在后续轮次再次被选中；已用渠道集合仅允许在单轮内去重 |
| 失败处理 | 进入内部转发后，只要本轮没有获得成功响应就继续下一轮；不受现有状态码重试表限制 |
| 次数上限 | **无限**；单轮候选耗尽或暂时无渠道只结束本轮，不结束整个请求 |
| 全挂 | 不伪装 200，也不因一次全挂立即返回最终失败；继续进入后续轮次等待恢复 |
| 流式已写出 | 无法干净换渠，停止 |
| 请求生命周期 | 鉴权、限流、解析、敏感检查与预扣费只执行一次；无限轮次只重做现有选路与上游转发 |
| 客户端断开 | 停止内部重放，避免无接收方的孤儿请求继续占用渠道 |
| 余额 | 不在本需求 |
| 失败渠道 | 现有熔断 / 自动禁用 |

### 代码锚点

- 重试环：`controller/relay.go` `Relay`
- 选渠：`service.CacheGetRandomSatisfiedChannel`（channel priority / model priority）
- 令牌布尔先例：`Token.CrossGroupRetry` → context（`middleware/auth.go`）
- 未开启本模式：行为与现网完全一致

## Requirements

### R1 — 令牌开关

- MUST 令牌级可用模式开关，默认关闭
- MUST 鉴权后写入 context，relay 可读
- MUST 管理端令牌创建/编辑可配置（形态对齐 `cross_group_retry`）

### R2 — 失败即重新发起完整重试轮次

- MUST 仅开启时生效
- MUST 失败不立刻回客户端；在站内用**同一请求**开启一轮新的内部执行
- MUST 选路 100% 复用现有算法，不新造排序/评分
- MUST 不受 `RetryTimes` 限制，不设置任何次数上限
- MUST 进入内部转发后，只要尚未获得成功响应就持续重放，不把中间失败返回客户端
- MUST 每轮重新建立选路状态；后续轮次允许再次选中前序轮次失败过的渠道
- MUST 单轮候选耗尽或暂时选不出渠道时进入下一轮，不得据此返回最终失败
- MUST 成功时把成功响应回客户端
- MUST 鉴权、限流、请求解析与预扣费不随内部轮次重复执行

### R3 — 硬边界（物理约束，非额外业务规则）

- MUST 流式已写出后不再换渠
- MUST 客户端断开或请求 context 取消后停止重放
- MUST 指定渠道时不因本模式强行跨渠（与现网一致）
- MUST NOT 改变未开启令牌的行为
- MUST NOT 伪造 200 成功体

### R4 — 失败渠道

- MUST 继续现有 `processChannelError` / 熔断 / auto-ban，不另造禁用逻辑
- MUST 熔断或禁用结果影响后续轮次的现有选路；模式本身不维护跨轮永久排除表

## Acceptance Criteria

- [x] AC1: 默认关闭；关闭时与现网一致
- [x] AC2: 开启后，失败在站内开启新的完整重试轮次，客户端不接收中间失败
- [x] AC3: 重试次数无限；单轮候选耗尽后继续下一轮，并可再次选择前序轮次使用过的渠道
- [x] AC4: 每轮选路仍走 `CacheGetRandomSatisfiedChannel`（priority 或 model-route chain）
- [x] AC5: 流式已写出后不再换渠
- [x] AC6: 渠道暂时全挂时不伪造成功、不忙循环，后续轮次在渠道恢复后可获得成功
- [x] AC7: 管理端可配开关，鉴权后生效
- [x] AC8: 内部轮次不重复鉴权、限流和预扣费；客户端取消可终止无限重放

## Out of Scope

- 余额兜底
- 新造选路算法
- 伪装成功
- 多实例重放状态同步
- 请求内容分类/敏感词（本模式不负责）
